# 근현대 전시전 기획하기 — 가상 전시 사이트

**근현대 전시전 기획하기** — 1910년 국권 침탈부터 현대까지를 다루는
한국사2 2학기 수행평가용 가상 박물관입니다.
**로비에서 전시실을 눌러 들어가고, 전시실마다 자료를 하나씩(모두 세 점)**
등록하는 구성입니다. 자료는 **유물·문화재**와 **역사적 사건 사진** 두 가지 가운데
고를 수 있고, 고른 종류에 따라 아래 서술칸이 묻는 내용이 바뀝니다. 태블릿에서 손가락으로 오가기 쉽도록 전시실 세 곳이 각각
따로 열리며, 다 만들면 세 전시실 전체를 PDF 한 파일로 제출합니다.

빌드 도구나 서버가 필요 없는 **순수 정적 사이트**(HTML/CSS/JS)입니다.
`index.html`을 더블클릭해도 열리고, GitHub Pages에 그대로 올려도 동작합니다.

---

## 폴더 구조

```
├── index.html            전시관 전체 — 로비와 세 전시실이 화면 단위로 들어 있습니다
│                         (로비: 히어로 · 전시실 고르기 · 도록 저장 · 수행평가 방법
│                          + 제1~3전시실 화면)
├── guide.html            학생용 사용 안내 (A4 한 장으로 인쇄됨)
├── assets/
│   ├── css/
│   │   └── style.css     전체 스타일 — 색·폰트·반응형·인쇄까지 모두 여기서 관리
│   └── js/
│       ├── gate.js       기획자 입장 화면(학번·이름) · 상단 기획자 표시줄
│       ├── main.js       접이식 메뉴 · 로비↔전시실 화면 전환 · 작성 상태 표시
│       ├── exhibit.js    전시 자료 카드 — 종류 선택 · 사진 첨부 · 삭제 · 자동 저장
│       └── export-pdf.js 전시 도록 PDF 저장
├── CHECKLIST.md          아이패드 사파리 최종 점검표
├── sample/               테스트로 뽑아 본 결과물을 넣어 두는 자리 (배포와 무관, 비워도 됩니다)
├── .nojekyll             GitHub Pages가 파일을 그대로 서비스하도록 하는 표식
├── .gitignore
└── README.md
```

- 모든 경로가 **상대 경로**라 어느 주소에 올려도 그대로 동작합니다.
- 외부 라이브러리를 쓰지 않습니다. 인터넷에서 가져오는 것은 구글 폰트 하나뿐이고,
  연결이 안 되면 기기에 있는 명조·고딕으로 자동 대체됩니다.

## GitHub Pages 배포 방법

### 1단계 — 저장소 만들기

1. GitHub에 로그인하고 오른쪽 위 **＋ → New repository**를 누릅니다.
2. **Repository name**에 이름을 넣습니다. 예: `history-museum`
   (이 이름이 나중에 주소에 들어갑니다. 영문 소문자와 하이픈만 쓰는 편이 안전합니다.)
3. **Public**을 고릅니다. ※ 무료 계정은 Private 저장소로 Pages를 쓸 수 없습니다.
4. **Create repository**를 누릅니다.

### 2단계 — 파일 올리기

터미널 없이 웹에서 올리는 방법입니다.

1. 만들어진 저장소 화면에서 **Add file → Upload files**를 누릅니다.
2. 이 폴더 안의 **내용물 전체**(`index.html`, `guide.html`, `assets` 폴더 등)를
   드래그해서 올립니다.
   > 폴더 자체가 아니라 **폴더 안의 파일들**을 올려야 합니다.
   > `index.html`이 저장소 최상단에 보여야 정상입니다.
3. 아래 **Commit changes**를 누릅니다.

명령줄을 쓴다면:

```bash
git init
git add .
git commit -m "가상 박물관 사이트"
git branch -M main
git remote add origin https://github.com/<내아이디>/<저장소이름>.git
git push -u origin main
```

### 3단계 — Pages 활성화

1. 저장소 위쪽 **Settings**(설정) 탭을 누릅니다.
2. 왼쪽 메뉴에서 **Pages**를 누릅니다.
3. **Build and deployment** 항목에서
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / 폴더는 `/ (root)`
4. **Save**를 누릅니다.

### 4단계 — 주소 확인

1. 저장 후 1~2분 기다렸다가 **Settings → Pages** 화면을 새로고침합니다.
2. 맨 위에 `Your site is live at ...` 이라는 초록색 안내와 주소가 나타납니다.

```
https://<내아이디>.github.io/<저장소이름>/
```

3. 저장소 메인 화면 오른쪽 **Deployments** 또는 **Actions** 탭에서
   배포가 끝났는지(초록 체크) 확인할 수 있습니다.

### 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 404 페이지가 뜬다 | `index.html`이 저장소 **최상단**에 있는지. `assets` 폴더 안에 들어가 있으면 안 됩니다. |
| 글자만 나오고 디자인이 깨진다 | `assets/css/style.css`가 함께 올라갔는지. 폴더 구조가 유지되어야 합니다. |
| 수정했는데 그대로다 | 배포에 1~2분 걸립니다. 그래도 그대로면 브라우저 새로고침(Ctrl+Shift+R). |
| 주소가 아예 안 보인다 | 저장소가 Private이면 무료 계정에서는 Pages가 켜지지 않습니다. Public으로 바꾸세요. |

### 배포 후 꼭 알아둘 점

**주소가 바뀌면 학생이 작성한 내용은 따라오지 않습니다.** 저장 위치가 브라우저의
사이트별 저장소(localStorage)라 `file://`로 열었을 때와 `github.io`로 열었을 때가
서로 다른 공간입니다. 배포한 뒤에는 **처음부터 배포 주소로만** 작업하게 하세요.

## 사이트 기능

### 입장 화면 (학번·이름)

처음 들어가면 학번·이름 입력 화면이 먼저 뜨고, 입력 전에는 본문이 보이지 않습니다.
주소창에 `index.html#room2`처럼 특정 전시실을 직접 쳐서 들어가도 똑같이 막힙니다.
입장 후에는 화면 위쪽에 `기획자 11101 · 홍길동`이 표시되고,
옆의 **학번·이름 수정** 버튼으로 언제든 고칠 수 있습니다(작성 내용은 그대로 유지).

**입력과 동시에 페이지 제목이 `학번_이름`(예: `11101_홍길동`)으로 바뀝니다.**
브라우저는 PDF로 저장할 때 페이지 제목을 파일 이름으로 쓰기 때문에,
아이패드에서 *공유 → 파일에 저장*을 눌러도 `11101_홍길동.pdf`로 채워집니다.
학번·이름을 지우면 원래 제목으로 돌아갑니다.

표시줄의 **로그아웃**은 학번·이름과 세 전시실 내용(`museum-` 으로 시작하는 저장값)을
모두 지우고 처음 입력 화면으로 되돌립니다. 되돌릴 수 없으므로 누르면 한 번 물어봅니다.
공용 아이패드를 여러 학생이 돌려 쓸 때 쓰면 됩니다.

> 과제용 화면 가리개이지 보안 장치가 아닙니다. 브라우저 저장소를 지우거나
> 자바스크립트를 끄면 열립니다. 민감한 개인정보는 넣지 마세요.

### 화면 구성

`index.html` 하나에 모든 것이 들어 있지만, 화면은 네 개로 나뉩니다.
`main.js`가 주소의 `#`을 보고 한 번에 하나만 보여 줍니다.

```
로비(#lobby) ─ 히어로 · 전시실 고르기(카드 3개) · 도록 저장(#export) · 수행평가 방법
   │  카드를 누르면
   ├─→ 제1전시실(#room1) ─┐
   ├─→ 제2전시실(#room2) ─┤ 전시실 안에서 서로 오가거나 로비로 돌아올 수 있음
   └─→ 제3전시실(#room3) ─┘
```

- 전시실 카드·상단 메뉴·`index.html#room2` 같은 주소 모두 같은 방식으로 열립니다.
- 브라우저 뒤로 가기도 그대로 동작합니다(주소의 `#`만 바뀌는 구조).
- 로비의 전시실 카드에는 `아직 비어 있음 / 작성 중 / 작성 완료`가 표시됩니다.
- 자바스크립트가 없으면 화면을 나누지 않고 예전처럼 전부 이어서 보여 줍니다.

### 전시 자료 카드

**전시실마다 자료 하나씩, 모두 세 점**을 전시하는 구성입니다.
각 전시실에는 빈 카드가 한 장 놓여 있고, 그 이상 늘릴 수 없습니다.

| 구성 | 하는 일 |
|---|---|
| 자료 종류 | **유물·문화재** / **역사적 사건 사진** 중 선택. 아래 라벨·예시 문구가 함께 바뀜 |
| 사진 첨부 | 액자 안쪽을 눌러 파일 선택, 또는 이미지를 끌어다 놓기. 누르면 교체, ‘사진 삭제’로 비움 |
| 서술칸 ① | 유물·문화재 → `유물 설명` / 사건 사진 → `사진 속 장면 설명` |
| 서술칸 ② | 유물·문화재 → `관련 역사적 사건` / 사건 사진 → `사건의 배경과 의미` |

서술칸은 글자 수 제한이 없고, 줄이 늘어나면 칸 높이가 자동으로 늘어납니다.
**종류를 바꿔도 이미 쓴 글은 지워지지 않습니다**(빈 칸의 예시 문구만 바뀝니다).
저장되는 값에 `kind`(`artifact` · `event`)가 함께 들어가며, 도록 PDF의 항목 이름과
서술칸 제목도 이 값을 따라갑니다. `kind`가 없는 예전 데이터는 유물·문화재로 봅니다.

카드가 한 장 있으면 **＋ 자료 등록** 버튼은 저절로 숨겨집니다.
다른 자료로 바꾸려면 카드 오른쪽 위 **×**로 지운 뒤(확인 후) 다시 등록하면 됩니다.

전시 점수를 바꾸려면 `assets/js/exhibit.js` 위쪽 두 값을 고칩니다.

```js
var DEFAULT_CARDS = 1;   // 처음 놓이는 빈 카드 수
var MAX_CARDS = 1;       // 한 전시실에 전시할 수 있는 자료 수
```

> 이 제한은 새로 놓이는 카드에만 적용됩니다. 예전에 여러 점을 등록해 둔 브라우저에서는
> 저장된 내용을 지우지 않고 그대로 보여 주며, 추가 버튼만 숨습니다.

### 자동 저장

입력한 글과 사진은 브라우저 저장소에 자동 저장됩니다(전시실별로 따로).
사진은 가로세로 최대 1200px, JPEG로 자동 축소해 보관합니다.

- 다른 기기·다른 브라우저에서는 보이지 않습니다.
- 인터넷 사용 기록·사이트 데이터를 지우면 함께 지워집니다.
- 시크릿 모드에서는 저장되지 않습니다.
- 저장 공간이 차면 화면에 빨간 글씨로 알려 줍니다.

### 전시 도록 PDF

**PDF로 저장** 버튼은 ① 화면 맨 위 기획자 표시줄, ② 각 전시실 아래쪽,
③ 로비의 ‘전시 도록 내려받기’ 칸 — 세 곳에 있습니다. 어느 버튼이든,
지금 어느 전시실을 보고 있든 **저장소에 있는 세 전시실 전체**를 모읍니다.
누르면 표지(제목·기획자·과목·작성일·목차)와 제1~3전시실의 자료가 순서대로 담긴
인쇄 창이 열립니다. 프린터를 고르는 칸에서 **‘PDF로 저장’**을 선택하면 됩니다.

- 파일 이름은 **`학번_이름.pdf`**로 미리 채워집니다.
  (인쇄 직전에 문서 제목을 학번_이름으로 바꿔 두는 방식입니다.
  브라우저 정책상 저장 위치까지 자동으로 정할 수는 없어, 저장창은 직접 눌러야 합니다.)
- 아이패드 사파리는 인쇄 창 → 오른쪽 위 **공유 → 파일에 저장** 순서로 저장합니다.
- 사진·글이 모두 빈 카드는 도록에서 빠집니다. 사진만 없으면 ‘사진 없음’으로 들어갑니다.
- 자료 카드는 페이지 중간에서 잘리지 않고 카드 단위로 넘어갑니다(A4 세로 기준).
- 각 항목에 `유물 · 문화재` / `역사적 사건 사진`이 함께 적히고, 서술칸 제목도 종류를 따릅니다.
- 그림이 안 나오면 인쇄 설정에서 **‘배경 그래픽’**을 켜 주세요.
- 버튼 대신 브라우저 인쇄(Ctrl+P · 공유▸프린트)를 눌러도 세 전시실이 모두 담깁니다.
  (`beforeprint` 시점에 도록 문서를 대신 만들어 둡니다.)
- 도록의 전시실 제목·목차 번호는 화면과 같은 전시실별 색으로 인쇄됩니다.

## 디자인 바꾸기

어두운 전시장 벽(차콜)에 **탭·버튼·카드로 색을 얹는** 구성입니다.

- 사이트 전체 색은 `assets/css/style.css` 맨 위 `:root` 블록에서 관리합니다.
  기본 포인트색은 `--c-gold`(금색) 하나만 고치면 전부 따라옵니다.
- 전시실별 색은 같은 파일 **6-2 전시실별 테마**에서 `.theme-room1/2/3` 값만 고치면 됩니다.
  (제1실 청자 옥빛 `#8cbaa9` · 제2실 횃불 주홍 `#dd8a5e` · 제3실 새벽 하늘빛 `#6ea8dc`)
- 색이 들어가는 자리: 상단 탭(현재 위치), 전시실 카드 윗줄 띠와 바탕,
  전시실 이동 버튼, 단계 카드의 세로 획, 도록 저장 상자와 버튼, 전시 라벨.
- 색을 고를 때는 어두운 바탕에서 글자 대비 **4.5:1 이상**을 지켜 주세요.
